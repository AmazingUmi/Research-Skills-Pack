# 科研写作交接与模板

交接中的信息要能让下一个角色独立定位材料、判断可以采用的陈述并继续工作。可以写在回复里，需要可复用的交接时再按约定保存文件。已有交付物用已有文件名，以下字段按任务取用。

## 任务卡

| 字段 | 怎么写 |
| --- | --- |
| 目的与范围 | 交付物、章节或图件范围、语言、格式、只给建议还是实际写入 |
| 依据与版本 | 题目与提纲版本、素材与来源、材料或分析版本、模板与指南、允许使用的语料、引用截止日期（若有） |
| 使用约束 | 目标语言、作者要求保留的术语、比较范围、引用格式与工具约束。整稿将同一 `integrity_mode`（`default` 或 `strict`）交给写手、两次核查及最终导出，断点恢复沿用已记录的选择 |
| 角色与分支输入 | 负责角色及模式或内部流程、主张 ID、原材料位置和前置条件 |
| 分支输出 | 预期的图件、文献证据、具体章节或审稿问题清单，标明谁可写入主稿及文件位置 |
| 未决事项 | 暂缺什么、影响哪些主张、能继续完成哪些产物 |

## 证据矩阵

沿用已有 ID。从零开始可用 `C-001` 表示主张、`F-01` 表示图件、`R-001` 表示审稿问题。状态取“已支持”“待核”“缺证据”或“冲突”。一项有支持但覆盖范围有限时，把已支持的子陈述与待核的扩展陈述分开。

| 主张 ID | 拟写陈述 | 证据与定位 | 核验状态 | 可以怎样使用 |
| --- | --- | --- | --- | --- |
| C-001 | 指定档案中的两份记录采用了不同分类标准 | 档号、版本、页码与对应摘录 | 已支持 | 限定到所查记录及其语境 |
| C-002 | 这一差异普遍存在于同一时期 | 手头材料只覆盖上述两份记录 | 缺证据 | 作为待检验的延伸判断 |
| C-003 | 两组样本在指定指标上有差异 | 数据版本、汇总表位置、比较条件与统计定义 | 已支持 | 限定到所分析样本和该指标 |

## 各角色交接时附什么

| 角色 | 给下一个角色的最少信息 |
| --- | --- |
| 编排 | 当前阶段、稿件版本、核查结论及未决项、作者决定、下一角色与任务范围 |
| 大纲 | 各节的问题与主张、证据定位、要补的引用和图，对应优先级 |
| 文献 | 主张 ID、引文键、书目和阅读版本、原文节页或位置、引用支持范围、待核点。分开记录书目身份和论断核验 |
| 图表 | 图件 ID、路径与图注、源材料定位、支持范围及生成依据。定量图附指标、单位与汇总口径，示意图附组成与关系的来源 |
| 正文 | 稿件版本与变更区段、关键主张及采用的证据、引用和图件键、仍需核对的问题 |
| 审稿 | 问题 ID、位置与严重程度、主张 ID（可关联时）、证据与最小处理方式。返修回复另保留原审稿编号 |

## 汇合与版本追踪

1. 编排者对照交接物和本次输入，检查不同分支的材料版本、样本或文本范围、方法、定义与文献版本是否一致。有冲突时并列来源与适用范围，并决定哪些说法可进入稿件。
2. 每项主稿改动由当期指定的写入者整合。整稿组稿时由 `draft section` 或 `draft full` 汇入已验收的引用、图件和证据，授权返修时由 `review revise` 写入修订候选。文献、图表和审阅角色的辅助工作写到各自的交付物，最终写入者检查交叉引用和编号。
3. 改稿时注明基线、候选、触发问题、差异和核对结果。只重新发布变更后的关键产物。下游使用旧图、旧引文或失效论断时按最新有效版本更新。

## 严格模式：与 Material Passport 的对应

默认使用上面的任务卡和证据矩阵。启用严格模式时，交接改用 [`@/engine/handoff_schemas.md`](../engine/handoff_schemas.md) 中的结构化 schema，并由 `engine/scripts/` 的脚本校验。两者的对应关系如下，转写时不丢信息：

| 证据矩阵 | 严格模式中的位置 |
| --- | --- |
| 主张 ID、拟写陈述 | Claim Intent Manifest 的主张条目；正文中的引用标记 |
| 证据与定位 | Bibliography 的来源对象与 `literature_corpus[]` 条目（引用键、版本、页码或段落定位、实际读到的范围） |
| 核验状态（已支持、待核、缺证据、冲突） | 引文核验摘要与完整性报告（Schema 5）中的逐条结果；无法核验的保留为未解决项 |
| 审稿问题 `R-001` 等 | 审稿报告（Schema 6）的 weakness 对象与返修路线图条目 |
| 图件 ID、路径、图注 | 图件清单中的路径及图注，通过稳定的 `artifact_id` 连接 [`figure_table_trace[]`](../roles/figures/make/ars-visualization/references/vlm_figure_verification.md) 的来源、变换、支持的主张和局限 |
| 版本与基线 | Material Passport（Schema 9）的版本记录与阶段历史 |

新主张采用 C-001 起的编号。已有材料转入严格清单时保留旧键，登记映射，例如 `(原清单 A, C-01) → (严格清单 B, C-001)`。先核查新清单内编号唯一，先保留合法的现有三位键，发生碰撞时为其他旧键分配下一个空号。把下表随证据矩阵存入本次交接，图件、引用与审稿意见按复合键回链，恢复时读取原表。下表的 A、B 表示清单名称，实际严格清单记录完整的 `manifest_id`。

| 原清单 | 原主张 ID | 严格清单 | 严格主张 ID | 已有关联示例 |
| --- | --- | --- | --- | --- |
| A | C-001 | B | C-001 | R-001 |
| A | C-01 | B | C-002 | F-01、R-002 |

缺少字段的材料留在待核表；缺失必填整数年份的文献进入拒收日志，核实年份后才登记为可引条目。
