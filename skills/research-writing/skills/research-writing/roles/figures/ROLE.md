# 处理科研图表

本角色负责每张图的证据、表达和验收。生成与审查交给下表的模式，结果由本角色按下文流程核对。

## 模式

| 模式 | 什么时候用 | 文件 | 交付 |
| --- | --- | --- | --- |
| `make`（默认） | 制作或修订投稿级数据图、多面板图、图形摘要或机制示意图 | [make](make/MODE.md) | 图件、绘图脚本与 QA 结果 |
| `audit` | 审查图件是否忠实、可读、无障碍，核对不确定度展示与导出规格 | [audit](audit/MODE.md) | 问题清单与修法 |

整稿时先核对和复用用户提供或图表分支已交回的图件，沿用其图件 ID 与稿件标签。任务确有制作或改图需求时，由本角色为每张图选一条生成路径。需要 APA 7 定量图和 LaTeX 插图代码时，可在 `make` 下使用 `make/ars-visualization/` 的 ARS 绘图代理。图注中的统计口径用 `$research-writing draft stats-report`，需要先计算统计量时用 `$research-writing draft analysis`。`audit` 交付检查结果和修法，落实改图时使用 `make`。

## 先确定任务和输入

根据用户请求执行规划、生成、改图、补图注或验收。每张图只推进到所需的步骤。规划可交付图件任务卡，核对可直接交付问题表。整稿协作时，读取 [交接约定](../../references/handoff.md) 并沿用原有图件、标签和主张 ID。

| 输入 | 核对内容 |
| --- | --- |
| 图件计划或用户要求 | 图件 ID、图型、对应主张、需要表达的关系、目标位置、尺寸比例、格式与截止范围 |
| 定量资料 | 原始记录或核定汇总表、数据版本或记录编号、样本与条件、指标与单位、分组、聚合和不确定性定义 |
| 定性资料或文献摘录 | 资料范围、来源与定位、纳入与编码规则、主题或证据类型及其支持范围 |
| 方法或概念材料 | 步骤、节点与关系的来源，连接方向及含义，实作、推导与解释各自对应的证据 |
| 已有图件与版式 | 文件实际路径、可读性、图注、图例、稿件标签、投递规格，以及用户允许修改的元素 |

## 每张图的处理流程

### 1. 规划证据和视觉表达

1. 先写一句待展示的关系，关联已有主张 ID 或给新图分配图件 ID，例如 `F-01`。按任务选择结果图、证据表或示意图。多张图独立时，可以并行形成各自的任务卡和图件。
2. 定量图先明确源表和具体行列，再确定面板、横纵轴、单位、对照、排序、分组和聚合。分清观测单位与汇总单位，例如按个体直接汇总或先按地点汇总。确认误差棒来自标准差、标准误或置信区间中的哪一种。
3. 证据表用原文、材料或观察记录填充，交代纳入范围和分类依据。概念图先列节点、关系及方向，再区分流程先后、实测关联、理论推导和假设。用标签说明证据属性，只有材料能支持因果时才用因果箭头。
4. 需要视觉示例时优先查看用户给的稿件或期刊样图，把借鉴范围限制在布局、图例和标注。图表的实质内容以数据、材料或方法来源为准。

### 2. 定样式并生成

- **结果图与证据表。** 使用可复核的工具生成显式数值、刻度、图例或来源列。按材料采用排版表格、电子表格、统计绘图或已有绘图脚本。执行脚本前核对输入、运行条件和输出位置。相同分组跨图沿用颜色、标记或线型。遇到截断轴、对数轴或不同面板比例时明确标注。
- **方法或概念示意图。** 用可控绘图方式明确节点与关系，按交稿规格输出可编辑或适合印刷的格式。先核对结构，再调整字体、分组、留白和版式。把核心关系定位到方法说明、理论材料或实现记录。
- **已有图件。** 确认文件存在、指向正确版本，且图注、标签、单位、所对应资料和稿件提法一致。图件能打开但数据来源无法核对时，可以确认版面并标记证据为“待核”。只做版式时维持原数据的轴、范围、分组和含义。

### 3. 双检、修订和图注

1. 先核对**数据与结构**。对定量图表逐项核查数值、来源行列、单位换算、坐标尺度、对照和聚合。对证据表核对摘录、编码和来源。对示意图逐条核对节点、关系和注释。证据不足或口径冲突时标出具体面板与来源，必要时暂停该部分交付。
2. 再核对**可读性与引用**。按成稿字号检查标注、图例、裁切、重叠和对比度。需要迭代时记录问题、修法与复核结果，复核通过后交付。只请求核对时给修法，不改原图。
3. 为核验后的版本撰写图注，保留图中关键比较条件、指标及其统计口径和各面板含义，对异常点或缺失组提供读图说明。稿件自动编号时，图注省略手写的 Figure 编号。

## 交付与异常处理

| 情况 | 交付方式 |
| --- | --- |
| 源数据可核、图件已生成并检查 | 返回图件路径、图注、ID、稿件标签、数据定位、绘图入口和检查结果 |
| 用户只要求图件计划 | 返回任务卡，写清所需数据、布局、单位、聚合与待确认项 |
| 图件存在但证据缺失 | 返回可核部分，例如版式、单位或路径，标记各未核项和它影响的主张 |
| 穷尽可用资料后发现切分不一致 | 分面标出真实口径，或仅交付同口径部分。把未能比较之处说明清楚 |
| 无法生成某张图 | 记录图件 ID、所缺材料或运行障碍，继续推进独立图件或可单做的核对 |

采用状态“已支持”“待核”“缺证据”“冲突”描述图与对应主张的证据关系。交给正文角色时保留精确文件名、扩展名和标签，记录图注对应版本。只有在任务要求适配原项目时才另行生成它的 `figures/info.json`。

**调用示例。** “用 `$research-writing figures` 把这几份访谈摘要整理成主题证据表，再给一版图注。”为每个主题保留纳入标准、摘录编号与来源定位。只有资料支持时才增加频次，并注明统计单位。

## 验收模式结果

模式交回的图件由本角色按上文“双检、修订和图注”核对：数据与结构先核，可读性与引用后核；图注保留比较条件、指标与统计口径；路径、标签和图件 ID 交给正文角色。模式不可用时，由本角色按上文流程完成能独立交付的部分，并注明未完成的检查。
