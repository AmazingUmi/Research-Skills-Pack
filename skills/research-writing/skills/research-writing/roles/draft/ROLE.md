# 写作科研正文

本角色负责稿件的唯一写入：确定写作范围，整合证据、引文和图件，核对数字与引用后写入稿件。具体写作交给下表的模式，交回的文字由本角色核对后写入。

## 模式

| 模式 | 什么时候用 | 文件 | 交付 |
| --- | --- | --- | --- |
| `section`（默认） | 起草或重构指定章节、论证或首次投稿材料 | [section](section/MODE.md) | 指定章节的正文 |
| `full` | 从研究材料写出整篇初稿 | [paper](paper/MODE.md) | 完整初稿 |
| `abstract` | 写摘要与关键词 | [paper](paper/MODE.md) | 摘要与关键词 |
| `polish` | 润色、翻译、压缩已有文字，修 LaTeX 版面 | [polish](polish/MODE.md) | 修订稿或修改建议 |
| `stats-report` | 写或审查统计方法小节、结果与图注中的统计报告 | [stats-report](stats-report/MODE.md) | 统计报告段落或问题清单 |
| `analysis` | 需要做检验、效应量、功效或贝叶斯分析 | [analysis](analysis/MODE.md) | 计算结果与方法说明 |
| `data-availability` | 数据与代码可用性声明、数据仓库选择 | [data-availability](data-availability/MODE.md) | 声明文本与数据集引用 |
| `disclosure` | 按目标期刊政策写 AI 使用声明 | [paper](paper/MODE.md#disclosure) | AI 使用声明 |
| `format-convert` | 在 LaTeX、DOCX、PDF、Markdown 之间转换，或转换引用样式 | [paper](paper/MODE.md) | 转换后的稿件 |

带单位和不确定度的数字可用 Research Engineering 的 `uncertainty-and-units` 核算（另行导入）。研究计划、开题报告和项目申请书不属于本角色，使用独立技能 `nature-proposal-writer`。

## 输入与边界

确认目标章节、语言、用途、交付格式和编辑范围。单独调用时直接用用户提供的证据，无须先构造全套大纲。整稿协作时接收 [交接清单](../../references/handoff.md)，约定单一写作者整合主稿，其他角色交独立证据、图件与意见。

| 输入 | 这份材料决定什么 |
| --- | --- |
| 现有稿件、模板或目标期刊要求 | 哪些段落需要填补，允许写哪些文件，格式、语言、篇幅、匿名和引文样式 |
| 大纲、方法材料、已有引言与相关工作 | 章节要回答的问题、已建立的主张、术语、定义和叙事范围 |
| 研究记录、原始材料或分析结果 | 实际观察、材料范围、分析或实验条件、可比较口径和数字来源 |
| 理论材料或推导 | 定义、假设、适用条件，以及各论点可追溯的论证步骤 |
| 文献记录、图件与索引 | 可使用的引文键及支持范围，图件可用性、精确路径、标签和图注 |

## 写作流程

### 1. 确定段落任务与其证据

1. 找出用户要求的空节、新段落或指定修改处。为各段写清一个要回答的问题，以及需要哪种方法证据、结果证据或引用。沿用已有主张 ID，必要时给关键新主张标注 `C-01` 一类 ID。
2. 将主张映射到可核来源。实证主张定位到数据表、原始记录或摘录编号，理论主张定位到相应假设、定义或推导，文献主张定位到引文键及支持它的节页。已有图件附图件 ID 和标签。有冲突时列出两边来源，优先用与该主张口径一致且能核实的记录。
3. 记录每项关键主张的状态“已支持”“待核”“缺证据”或“冲突”。区分直接观察、材料解释、理论推导与待验证假设。支持范围有限时收窄陈述，或将未解决的问题纳入待核清单。

### 2. 按章节职责组织文字

| 章节 | 能交付的内容 |
| --- | --- |
| 摘要 | 问题、方法、研究范围、已核结果或论证结论和主要贡献。引用数字时与正文保持同一口径 |
| 引言与相关工作 | 背景、研究空缺、位置和贡献。此两节已有定稿时仅引用，用户要求修改时按已核文献重写指定范围 |
| 方法与理论 | 交代材料来源、取样或选择规则、分析步骤、定义和假设。涉及实验、编码、实作或推导时，按实际研究设计写明条件和过程 |
| 结果与分析 | 根据体裁呈现实证发现、主题分析或论证过程。数量比较给出分组和统计口径，质性发现附材料位置，理论结论注明适用假设 |
| 讨论与结论 | 交代哪些证据或推导支持哪些主张，读者可以外推到哪里。按材料范围写清例外、替代解释和研究限制 |
| 附录 | 用户需要时收纳能复现且超过正文篇幅的细节，沿用投稿模板中的层级和交叉引用 |

### 3. 核数、核引、核图后整合

- **数字与表格。** 按来源行列逐项匹配值、观测单位、样本范围、比较条件与统计量。优先保留来源数字及有效精度。相对差异和百分比应有明确分母、可比条件和可复核计算。
- **摘录与命题。** 核对引文或语料对应的位置、版本及分析语境。涉及理论命题时保留适用假设，按来源区分已证明的结论与待证明的解释。
- **引文。** 使用已核引文及其现有键。逐条确认引用对邻近陈述的支持范围。只有摘要可见时，以摘要可以核实的内容为界。没有键、缺相应书目或歧义待核时，先收窄句子或标记待补。
- **图件。** 引入已有文件确认过的精确文件名、标签和图注。描述结论前核对图及底层证据。只有图注可看时只写它已经核实的信息。图件缺失时保留待插入说明，避免产生误导性的图号或交叉引用。
- **稿件格式。** 只编辑授权位置，保留原有层级、匿名约定和引用体系。Word 或 Markdown 视需要检查标题、图表编号与交叉引用。LaTeX 保留导言区、宏和文档类，并检查图件路径、环境和参考文献键。只有交付范围需要构建时才按可用入口执行，并报告实际检查结果。

### 4. 用稿件差异检查交付

确认每项要求都有对应段落，正文、表格、图注中的同一指标口径一致，所引用的图件和文献能定位，未授权章节保持原样。提交稿件片段或所改文件、关键主张与来源，以及需要人工确认的缺口。长稿可附变化说明和最小证据表。

| 常见缺项 | 处理方式 |
| --- | --- |
| 同名指标来自不同样本、条件或聚合 | 对照来源分别标注实际口径。只把可比条件纳入直接数值对比 |
| 缺观测记录、原文或论证步骤 | 完成材料充分的段落，注明还需哪份证据，相关推测先写成明确的假设或留空 |
| 缺图、引用键或无法查看图件 | 先交付可被证据支持的段落，记录具体插入位置与待补项 |
| LaTeX 候选出现构建错误 | 定位本次改动触发的错误，修理授权范围内的内容，保留上一版可用稿件和构建信息 |

**调用示例。** “用 `$research-writing draft` 把这份推导笔记写成理论部分第一段，保留定理的适用条件。”核对定义、假设和推导步骤，区分已证命题与延伸解释。只交这一段及对应出处。

## 验收模式结果

模式交回的文字由本角色按上文“核数、核引、核图后整合”核对：数字与来源一致，引用支持邻近陈述，图件能定位，未授权章节保持原样；之后再写入稿件。模式不可用时，由本角色按上文流程完成能独立交付的部分，并注明未完成的检查。
