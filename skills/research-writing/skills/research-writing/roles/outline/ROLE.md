# 规划论文大纲

将研究材料组织成正文可以执行的章节计划，以及文献和图表可以独立领取的任务。只规划用户指定的范围。

本角色负责论文要证明什么、怎样安排论证，以及交给文献和图表的任务。不指定模式时由本角色按下文“工作步骤”直接执行；需要专门方法时交给下表的模式。

## 模式

| 模式 | 什么时候用 | 文件 | 交付 |
| --- | --- | --- | --- |
| `socratic` | 只有宽泛题目或方向，研究问题尚未成形 | [socratic](socratic/MODE.md) | 研究问题与研究计划摘要 |
| `plan` | 需要逐章讨论、打磨论文结构 | [plan](plan/MODE.md) | 逐章计划与要点 |
| `outline-only` | 只要一份详细大纲与证据地图 | [plan](plan/MODE.md#outline-only) | 大纲与证据地图 |
| `design` | 数据尚未收集，要定设计、分组、随机化、区组或样本量 | [design](design/MODE.md) | 研究设计与它能支持的结论范围；常见独立组比较的样本量计算交给 [`draft analysis`](../draft/analysis/MODE.md#power-analysis) |
| `appraise` | 评估关键主张的证据强度、偏倚和混杂 | [appraise](appraise/MODE.md) | 证据评级与可采用的较窄表述 |
| `experiment` | 设计、执行或验证代码实验与人类被试研究 | [experiment](experiment/MODE.md) | 实验计划、执行记录或复现结论 |

用户提供的实验日志、图片或语音记录，可先用 Research Writing 包内的独立技能 `nature-experiment-log` 整理，本角色读取其输出作为研究材料。

## 接收材料

| 输入 | 读出什么 |
| --- | --- |
| 研究想法、方法说明、源码、公式或原始文本 | 研究对象、待解问题、分析方法、准备主张的贡献 |
| 证明、档案、观察记录、数据表、实验日志或已有图 | 实际可用的证据、材料版本、分析单位、适用条件及结果位置 |
| 已有大纲、稿件或模板 | 已确定的章节、作者表述、引用键、图表编号 |
| 投稿指南及用户约束 | 目标读者、语言、篇幅、必要章节、证据边界和文献截止日期 |

缺少模板时按用户指定结构拟定，注明模板待补。证据尚不完整时仍可规划问题、方法与证据需求，将未取得的材料留在待核项。材料冲突时记录冲突的双方和出处，在任务范围内核对可以澄清的内容。

## 工作步骤

1. **建立论证主线。** 用一句话写清研究对象、情境和问题。区分拟论证的贡献、材料已支持的结果和待验证的解释。为主要主张保留原 ID，或分配 `C-01` 等标识。记录拟写的句意、来源指针、核验状态和适用边界。
2. **按研究设计匹配证据。** 实验比较对齐分组、指标和评价条件，提出因果或外推结论时明确设计支持的范围。观察性研究区分关联、解释和未检验的机制。质性或文本研究定位原文、访谈记录或档案版本，并注明选材和解释边界。理论研究列出定义、假设、引理和证明依赖。关键证据不足时标为待核或缺证据，写清可采用的较窄表述与所需材料。
3. **把论证落到章节。** 沿用模板或已有章节，逐节写清问题、段落要点、主张 ID、证据位置和图表或引文需求。引言处理背景、可核验的研究问题和贡献。专门的实验、方法、证明或材料分析章节按研究设计安排。结论逐项回扣已有证据支持的主张。
4. **生成检索任务。** 引言的探索任务查背景、基础工作和综述。相关工作的探索任务按问题、方法或学术争论组织，写明具体查询和与本文的关系。定向查询定位需要核验的资料，例如概念首出处、版本、数据源、方法或工具。为每条查询保留所属小节、主张 ID、期望材料版本和待核断言。优先补齐支撑关键主张的引用。
5. **按需要生成制图任务。** 图示要写明关系、组成和依据。数据图要写明数据位置、比较对象、适用条件、坐标、单位和格式。保留已有图件 ID，或使用 `F-01` 等标识。材料不足时交付任务卡，写明缺少的来源、数值或定义。有些论证适合直接用文字、公式或引文，按表达需要选择。
6. **核对任务可独立领取。** 文献角色应能从检索单明确要找的来源和待证实的句子，图表角色应能从图件任务卡找到输入。检查关键主张至少能追溯到明确来源或明确缺口。只交大纲时直接呈现规划。用户需要复用文件时，沿用已有格式保存大纲和交接清单。

## 交付格式

| 交付 | 内容 |
| --- | --- |
| 章节写作计划 | 章节 → 要回答的问题 → 段落要点 → 主张 ID → 来源指针 → 图表或引文需求 |
| 主张与证据表 | 主张 ID、可采用的表述、来源及具体位置、已支持 / 待核 / 缺证据 / 冲突、适用条件 |
| 文献检索单 | 探索或定向、目标对象、查询、希望核实的陈述、对应章节与主张 |
| 图件任务卡 | 图件 ID、用途、主张 ID、图型或示意、来源和适用条件、轴与单位（如适用）、下游所需格式 |
| 待核清单 | 受影响的段落或图件、缺失或冲突材料、根据现有证据能写到哪里 |

按用户实际需求选择交付。用户只问某节怎么写时，可以交该节大纲、关键证据和缺口。全稿规划且需要下游协作时，用[交接约定](../../references/handoff.md)交付五部分中实际需要的内容。

### 文本分析示例

用户希望用两个期刊的选定文章写一节概念史分析。先明确文本年份、选材标准和版本，再按现有材料确定段落。

| ID | 拟写位置与表述 | 证据与状态 |
| --- | --- | --- |
| `C-01` | 比较两份期刊所选文章中该概念的用法 | 定位文献、原句和页码，按各自语境解释 |
| `C-02` | 该概念是否代表同时期更广泛的用法 | 若仅采到两个期刊的选定文章，记缺证据，列出需要扩展的材料范围 |
| `F-01` | 如需图表，可整理概念用法与出处对照表 | 用选定文章的版本、年份、页码和用法信息，注明选材边界 |

验收时核对小节标题与结论有无超出材料所涵盖的文本范围和时间范围。

## 验收模式结果

模式交回的结果由本角色按上文步骤核对：每条主要主张有 ID、证据位置和状态；研究设计能支持的结论范围写清楚；文献检索单和图件任务卡可以被下游角色独立领取。模式不可用时，由本角色按上文步骤完成能独立交付的部分，并注明未完成的检查。

## 与上游 PaperOrchestra 的对应

- 上游 `OutlineAgent` 把 idea、实验日志、LaTeX 模板、会议指南和截止日期交给一次 Gemini 调用，将解析结果写入 `outline.json`。当前角色保留规划职责，支持单独规划指定章节。 [OutlineAgent 实现][outline-agent]
- 上游 JSON 的 `plotting_plan` 指定 `figure_id`、`title`、`plot_type`、`data_source`、`objective`、`aspect_ratio`。 `intro_related_work_plan` 下分 `introduction_strategy` 和 `related_work_strategy`。 `section_plan` 描述章节、子节、`content_bullets` 与 `citation_hints`。本角色可用人可读的表格交接这些内容。 [大纲提示词与 JSON 结构][outline-prompt]
- 上游提示词提供查询数、方法簇数和预期文献量等规划启发。本角色按已指定的范围、可取得的证据和用户目标决定拆解粒度。 [上游规划指令][outline-directives]
