# 默认完整性核查

接收当前稿件及其版本、参考文献、可用的原文和研究材料。有实验结果时使用提供的实验记录和数据表。有前一轮核查或审稿时，附遗留问题和稿件差异。沿用任务卡的 `integrity_mode: default`，在报告中记录稿件版本与此次核查模式，随稿交给下一阶段。使用[交接约定](../../../references/handoff.md)中的证据矩阵。默认核查可在会话中完成，无需 Python 引擎、Material Passport 或机器校验报告。严格核查使用[严格核查 Agent](integrity_verification_agent.md)。

## 核查范围

1. **参考文献。** 逐条核对条目的存在、版本和书目字段，并检查正文引用与列表能否对应。用实际来源核验。仅核实名录或 DOI 时，只记录书目核验结果。
2. **引用语境。** 对照稿件所引版本的原文，检查它是否支持对应措辞及其范围。阶段 2.5 抽查不少于三成的引用语境，并覆盖所有高影响主张涉及的引文。阶段 4.5 核对当前稿件中识别出的全部引用语境。
3. **数据与图表。** 将报告的数字、比较条件、样本、统计口径和单位与原材料对应。检查正文、表格、图和图注的数值及含义是否一致。
4. **原创性。** 按[原创性核查](../references/plagiarism_detection_protocol.md)默认仅比较已提供材料。对外检索前需作者明确授权服务及原句范围；获准后仅外查指定范围，记录抽查范围和可定位的重合。工具或来源不可用时，记录实际未查的部分。
5. **主张。** 记录主张 ID、稿件位置、证据位置、支持范围和四态结论。阶段 2.5 核对所有识别出的高影响主张（核心结论、数值、因果、关键方法和有争议的说法），对其余主张抽查并记录范围。阶段 4.5 核对识别出的全部定量和事实主张，并逐项复核前一轮的遗留问题。证据未覆盖的部分标为待核、缺证据或冲突。

两阶段都按 [AI 研究失败检查](../references/ai_research_failure_modes.md)登记七类检查结果。从任务卡读取用户对实际开展实验或分析的说明。说明缺失且影响判定时，请作者确认并记入任务卡。适用 PRISMA-trAIce 或 RAISE 时，在报告中按[项目](../../../references/prisma_trAIce_protocol.md)和[原则](../../../references/raise_framework.md)写明证据、缺项与影响。系统综述的 Mandatory 项未通过时，把它列入阻断项。

## 交回编排

- 报告包含阶段、稿件版本、各类核查覆盖范围、证据矩阵、按严重程度排序的问题和最小修正建议。阶段 2.5 的核验结果仅适用于检查过的材料。阶段 4.5 以当前完整稿件为基线执行全轮核查。
- 严重或中等问题、未核实的关键主张，以及按适用规则须阻断的检查项均记为失败。阶段 2.5 可带轻微问题通过并保留明细。阶段 4.5 还需解决轻微问题，范围说明与非阻断提醒继续随报告交接。
- 核查只交回报告。编排取得作者对修正项和改动范围的确认后，交给 `review revise` 写入修订候选。复查修正项和受影响的下游主张、数值、图表及引用，按[编排检查点](../ROLE.md#4-完整性核查阶段-25-与-45)记录修改范围、新版本和用户决定。
