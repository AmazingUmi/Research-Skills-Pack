# 编排科研写作

由本入口管理写作阶段、稿件基线和最终整合。需要多个角色、组装整稿或续接时，读[完整流程指南](references/workflow.md)。需要专项技能时，按[下层技能分工](references/writing-packs.md)为当前阶段选择所需能力。需要交接或审计证据时，读[交接约定与模板](references/handoff.md)。用户点名一个角色时，直接围绕指定产物执行。

## 选角色

| 用户需要 | 加载角色和交付重点 |
| --- | --- |
| 决定论文要证明什么、怎样安排论证 | [论文大纲](../paper-orchestra-outline/SKILL.md)，交付主张与证据表、写作顺序、检索和出图任务 |
| 查原始出处、核现有引用、组织综述 | [文献核查](../paper-orchestra-literature/SKILL.md)，交付可引用条目、原文支持范围和待核项 |
| 新画图、检查已有图，或补图注 | [科研图表](../paper-orchestra-figures/SKILL.md)，交付图件、图注、数据与绘图依据 |
| 写已有研究的指定章节，或整合多个分支 | [正文写作](../paper-orchestra-draft/SKILL.md)，交付稿件或规定范围内的修改 |
| 诊断论证与证据、审版、逐条回复或应用返修 | [审稿与返修](../paper-orchestra-review/SKILL.md)，交付问题清单、回复或获准写入的修订稿 |

## 组织工作

1. 确认本次要的产物和可修改范围。盘点已有大纲、研究材料、参考文献、图件和原稿。用户只想选角色时，给出最小组合、每个角色的交付物和现有材料缺口。用户委托执行时，按范围推进到交付。
2. 根据研究类型确定证据。定量工作核对研究设计、数据来源和分析版本，质性和文本研究核对原始材料、选样或编目范围及解释依据，理论工作核对定义、前提和推导。按用户的材料与交付要求选用合适的检查项。
3. 让各执行角色读对应说明。把要回答的问题、已有主张 ID、输入版本、预期输出和可写范围传给它。下层技能的结果先回到对应阶段，再由本入口协调下一步。输入独立时可并行执行文献和图表分支。正文由一个角色写入。无并行能力时按同一依赖顺序执行。
4. 汇合前核对各支线覆盖哪些主张、使用哪个版本、哪些仍待核。准备好的部分照常交给正文。缺失或冲突只限制受影响的论断。按用户提供的已有中间产物继续，修改时只重做失效的支线及其受影响的下游。

角色分工参考 [PaperOrchestra](https://github.com/google-research/paper-orchestra/tree/d9bae997e793a015ed38bb1605be9eb58c00284f)。本组以会话中的角色说明和可核对的交付物执行，流程指南记录了原实现与本组执行方式。
